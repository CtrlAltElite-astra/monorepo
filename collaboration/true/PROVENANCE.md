# Provenance: where this folder came from and what was changed

This folder is the **partner team's TRUE code**, written for CodeAstra 2.0 PS1 (privacy-preserving verifiable
identity). They authored it and own the idea; the SyncShield team (Lane C, Miti Shah) brought it into this repo and
adapted it so SyncShield members can sign in with a TRUE credential.

- **Source:** the partner team's TRUE repository (the `TRUE-main` copy given to the SyncShield team).
- **Cryptography:** none of it was rewritten. Credential issue, holder proof, selective disclosure and
  verification all run through the partner's `packages/credentials`, which wraps the open-source libraries listed in
  `README.md` (`@sd-jwt/sd-jwt-vc`, `@owf/crypto`, `jose`). SyncShield adds no cryptography of its own to this code.
- **Licence:** the partner repo does not ship a licence file; its README lists third-party libraries (Apache-2.0 and
  MIT). Ask the partner team before any use outside this hackathon.

## What was changed (10 files), and why

| File | Change | Why |
|---|---|---|
| `packages/credentials/src/index.ts` | `RESERVED_CLAIMS` guard in `issueCredential`; `verifyPresentation` also returns `meta` (`iss`, `iat`, `exp`, `vct`, `holderBound`) | Without the guard a claim named `exp` or `cnf` could replace the real value through the spread. `meta` gives regions the *verified* expiry and holder binding, so nothing is read from an unverified decode. Original result fields are unchanged |
| `packages/shared/src/index.ts` | Re-exports `syncshield.ts`; wallet URL port 5173 → 5183 | 5173 is the SyncShield dashboard |
| `services/issuer-api/src/app.ts` | Optional admin token on the student and claim-code routes; SyncShield claim-code profile returns only the minimal member credential; registers the SyncShield routes | Members, roles, revocation and the status list. Without the token the original behaviour is unchanged |
| `services/issuer-api/src/db.ts` | Calls an additive migration (new tables, `claim_codes.profile`) | Stores members and credential status. Existing tables untouched |
| `services/issuer-api/src/server.ts` | Port, data dir, registry and public-key output come from environment variables; admin token required in SyncShield mode; key file mode 0600; listens on 127.0.0.1 | Tests and the demo must not share state; the issuer key is never regenerated by accident; the admin routes fail closed |
| `apps/wallet/vite.config.ts` | Port 5183 | Same port reason as above |
| `package.json`, `package-lock.json`, `tsconfig.json` | Workspaces limited to `packages/*` and `services/*`; scripts that depend on the unvendored `contracts`/`apps` removed | The issuer-web, verifier-web and chain parts are not included here |
| `README.md` | Merge markers removed (the partner repo was committed mid-merge: a stub `# TRUE` on one side); vendoring note added | Readability only |

## What was not brought over

`PLAN.md` and `PS1.md` (the partner team's internal planning notes), `apps/issuer-web`, `apps/verifier-web`,
and `contracts/` (the local chain). SyncShield does not use a blockchain registry; trust comes from the issuer's
pinned public key and its signed status snapshot.

## How to check this table

Compare any file here with the partner's original; everything not listed above is byte-identical apart from line
endings. The SyncShield-specific parts are marked in the code with `SYNCSHIELD ADAPTATION`.

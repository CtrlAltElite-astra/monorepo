# Lane A hand-off (Akshit): the per-shopper limit and the scaling console

Branch `a/akshit-scale`, 13 October 2026. Contract: section 8 of `contracts/contracts.md` (v1.2), which this lane froze. `origin/main` (lanes B, C and D) is already merged into this branch, with no conflicts.

1. **Built, backend:** `region/api/ratelimit.py`, a token bucket per actor (`RATE_ACTOR_BURST`, `RATE_ACTOR_REFILL_PER_S`, off at 0; a refill of 0 means one burst and then nothing). It is spent in the write path right after the `op_id` replay check, so a retry is never refused or counted and a refused write stores nothing and uses no sequence number. An empty bucket answers 429 with the contract 8.3 body and headers; every accepted write and replay carries `X-RateLimit-Limit` and `X-RateLimit-Remaining`, and both are exposed through CORS. `ratelimit.snapshot()` feeds the status block, and `ratelimit.key(auth)` is the one line to swap for `claims.subject_key`.
2. **Built, console** (`frontend-new/`, complete in the simulator and checked against real regions): a "requests left" meter under each shopper and *Spam as* next to Burst and Tamper; a *Limit this region* switch and a route line that says why the browser moved; home regions and a writes-per-second bar on every region card; a low / medium / high dial; *Add Bengaluru*; Burst 300, Burst 1000 and Spread 1000 with measured results; and a Scaling tab that reads `public/scale-result.json` and says "not measured yet" when the file is missing.
3. **How to run it:** `cd frontend-new; npm run dev`, then open `http://localhost:5175/demo?mode=mock` (the simulator starts with the shopper limit on: 10 requests, one more every second). Real regions: `$env:RATE_ACTOR_BURST='10'` before `scripts/run_regions.py`, or switch it on from the console's Network tab. Checks: `pytest tests/api/test_ratelimit.py` (34 tests); whole repo `pytest tests` on the merged tree = 527 passed, 24 skipped (the Node-only tests of lanes B and C); `npm test` (109 tests); `npm run build`; `node .local/integration.cjs` (isolated real backends, 9 browser stages, all pass).
4. **Not finished, and why:** the region limit and the power dial do nothing on a region started from `region.main:app` until the hook below is wired (step J0). The simulator's power numbers are modelled, not measured, and so is its 74 / 328 / 494 a second. Buckets are in memory per region, so a shopper who moves starts with a full allowance there (it bounds load per region; it is not a quota). The meters are exact only when each shopper has an API key of their own (`VITE_SHOPPER_KEYS`, and `scripts/run_one.py` now provisions `dev-alice` and the others); with one shared key every shopper shares one allowance.
5. **Hooks left for the joining steps, off by default and not faked:** an empty `<div id="identity-slot">` in the shop column; a fourth Tamper row that appears only when `GET /v1/auth/status` says sign-in is on; the adults-only item behind `?restricted=1` (its note carries `"requires": "age_over_18"`); and a 403 `claim_required` that the console shows as a prompt, not an error.

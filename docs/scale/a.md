# Lane A hand-off (Akshit): the per-shopper limit and the scaling console

Branch `a/akshit-scale`, 13 October 2026. Contract: section 8 of `contracts/contracts.md` (v1.2), which this lane froze.

1. **Built, backend:** `region/api/ratelimit.py`, a token bucket per actor (`RATE_ACTOR_BURST`, `RATE_ACTOR_REFILL_PER_S`, off at 0). It is spent in the write path right after the `op_id` replay check, so a retry is never refused or counted and a refused write stores nothing and uses no sequence number. An empty bucket answers 429 with the contract 8.3 body and headers; every accepted write and replay carries `X-RateLimit-Limit` and `X-RateLimit-Remaining`. `ratelimit.snapshot()` is for the status block, and `ratelimit.key(auth)` is the one line to swap for `claims.subject_key`.
2. **Built, console** (`frontend-new/`, complete in the simulator): a "requests left" meter under each shopper and *Spam as* next to Burst and Tamper; a *Limit this region* switch and a route line that says why the browser moved; home regions and a writes-per-second bar on every region card; a low / medium / high dial; *Add Bengaluru*; Burst 300, Burst 1000 and Spread 1000 with measured results; and a Scaling tab that reads `public/scale-result.json` and says "not measured yet" when the file is missing.
3. **How to run it:** `cd frontend-new; npm run dev`, then open `http://localhost:5175/demo?mode=mock` (the simulator starts with the shopper limit on: 10 requests, one more every second). Real regions: set `$env:RATE_ACTOR_BURST='10'` before `scripts/run_regions.py`. Checks: `pytest tests/api/test_ratelimit.py` (33 tests); whole repo `pytest tests` = 470 passed, 18 skipped (the Node-only convergence tests of lane C); `npm test` (105 tests); `npm run build`; `node .local/integration.cjs` (isolated real backends, 9 browser stages, all pass).
4. **Not finished, and why:** the real backend cannot yet change limits or power at runtime, report `load`, or start Bengaluru (all lane D), so in live mode those controls say so instead of pretending, and writes per second is measured from each region's own write counter. Per-shopper meters on real regions need one API key per shopper: today every shopper uses `dev-officer`, so they share one allowance. The simulator's power numbers are modelled, not measured. Buckets are in memory per region, so a shopper who moves starts with a full allowance there (it bounds load per region; it is not a quota).
5. **Hooks left for the joining steps, off by default and not faked:** an empty `<div id="identity-slot">` in the shop column; a fourth Tamper row that appears only when `GET /v1/auth/status` says sign-in is on; the adults-only item behind `?restricted=1` (its note carries `"requires": "age_over_18"`); and a 403 `claim_required` that the console shows as a prompt, not an error.
